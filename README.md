# 将棋AI対戦（Webアプリ）

ブラウザで遊べる将棋AI対戦アプリです。先手/後手、AI強さ、思考時間を設定して対局できます。棋譜は日本語表記（「▲」「△」「同」「成」「不成」「打」）で右側に表示されます。

## 主な機能

- 先手/後手選択、AI強さ/思考時間の設定
- 盤面/持ち駒の駒画像表示（0枚は非表示）
- 直前の指し手ハイライト
- AI思考中のモーダル表示
- 日本語棋譜表示（固定高さ・スクロール）
- 好手/悪手の自動判定（青/赤で色分け）
- 次の一手ヒント（自分の手番におすすめの指し手と移動元・移動先を表示）
- 1手ごとの評価値グラフ（対局中・対局後に手数を選んで確認）
- 画面ごとのルーティング（/settings, /game, /result）
- やねうら王（USI）連携。失敗時はローカルAIへフォールバック

## 技術スタック

- Next.js (App Router)
- TypeScript
- Tailwind CSS

## セットアップ

### 1. 依存関係のインストール

```bash
npm install
```

### 2. USIエンジン（やねうら王）の用意

- 実行ファイルのパスを環境変数に指定します。
- macOS / Linux それぞれのバイナリを用意してください。

`.env.local`:

```bash
YANEURAOU_PATH=/absolute/path/to/engine
```

### 3. 開発サーバ起動

```bash
npm run dev
```

ブラウザで http://localhost:3000 を開きます。

### 学習モード

設定画面の「学習モード」で「次の一手ヒント」「評価値グラフ」を個別にオンにしてから対局を始めます。両方同時に利用でき、先手・後手どちらにも対応します。

- ヒントは自分の手番に自動表示されます。盤上の青い枠が動かす駒、青い丸が移動先です。持ち駒を打つ手や成る手も案内します。
- 評価値は開始局面と1手ごとの局面を記録します。プラスは先手有利、マイナスは後手有利です。グラフ下のスライダーで各手の数値を確認でき、対局結果画面にも表示されます。
- エンジンの評価値を使う場合は `.env.local` に `USI_EVAL_ENABLED=1` を設定します。解析は手順に沿って順番に行い、取得までは簡易評価を表示します。
- エンジンが使えない場合や評価が無効の場合も、ヒントはローカルAI、グラフは駒の価値・配置などによる簡易評価で動作します。評価の種類はグラフ下に表示されます。

### スマートフォン・タブレットでの対局

画面幅が1024px未満のときは、手番・盤面・持ち駒を常時表示し、下部の「ヒント」「評価」「棋譜」「メニュー」から情報を開きます。ヒントと評価のボタンは、それぞれの学習モードをオンにした場合に表示します。

情報は画面下部のモーダル内で切り替えられ、長い棋譜はモーダル内でスクロールします。「閉じる」、背景のタップ、Escapeキーで対局に戻れます。リセットと設定への移動は「メニュー」内にあります。PC幅に広げるとモーダルを閉じ、左右のパネル表示に戻ります。

## デプロイについて

- Linux 環境へデプロイする場合は Linux 向けバイナリを用意してください。
- AI設定（Threads/Hashなど）はサーバー側で調整済みですが、環境に合わせて見直してください。

- app/lib/game.ts : 対局の状態遷移・合法手の適用・終局判定（Reducer）

## 画面ルーティング

- /settings : 対局設定

## 主要な型（TypeScript）

定義は [app/lib/types.ts](app/lib/types.ts) を参照してください。

- `Owner`: 先手/後手を表す識別子（"b" / "w"）。
- `PieceType`: 駒種（"P" "L" "N" "S" "G" "B" "R" "K"）。
- `Piece`: 盤上の駒（駒種・所有者・成り状態）。
- `Board`: 9x9 の盤面配列。
- `Hands`: 持ち駒の数を保持する連想配列。
- `Move`: 指し手（移動/打ち、成り情報を含む）。

## 主要な関数

定義は [app/lib/shogi.ts](app/lib/shogi.ts) 経由で再エクスポートされています。

- `applyMove()`: 指し手を盤面/持ち駒に適用して新状態を返す。
- `buildLegalMoves()`: 盤面全体の合法手を生成。
- `getLegalMovesForPiece()`: 指定した駒の合法手を生成。
- `getLegalDropMoves()`: 打ち手の合法手を生成。
- `canApplyPromotionOption()`: 成り/不成の可否を判定。
- `isInCheck()`: 王手判定。
- `findKing()`: 王の位置を探索。
- `chooseAiMove()`: AIの指し手を選択（USI優先、失敗時ローカルAI）。
- `evaluatePosition()`: 盤面評価を取得（USI優先、失敗時ローカル評価）。

## 評価（好手/悪手）について

- 指し手評価は先手基準の評価値の変化で判定します。異なる種類の評価値同士は比較しません。
- サーバーのメモリが厳しい場合は評価を無効化できます。

無効化方法（Renderなど）:

```bash
USI_EVAL_ENABLED=0
```

この場合、エンジン評価のリクエストは初回以降省略し、簡易評価でグラフと棋譜の色分けを行います。

## 検証とパフォーマンス

```bash
npm test          # 将棋ルール・状態遷移・API入力・エンジンのライフサイクル
npm run lint
npm run build
npm run benchmark # 開始局面での探索処理を計測（5回の中央値）
```

ローカルAIの探索はWeb Worker上で行います。リセット・画面遷移時には探索と通信を中止し、古い応答は対局IDと手数を確認して破棄します。Web Workerを利用できない環境では、互換処理として探索を100ms・深さ2までに制限します。

サーバーのエンジン起動は1プロセスあたり同時2件、待機16件までに制限します。待機中の中止・エンジンの異常終了にも対応し、子プロセスの終了を待ってから枠を解放します。APIは64KiBまでのJSONを受け付け、盤面・持ち駒・手番・探索条件を検証します。

レビュー内容と計測結果は [コードレビュー記録](docs/code-review.md) を参照してください。

## ルールの対応範囲

二歩・行き所のない駒・王手放置・打ち歩詰めを禁止し、成り/不成・詰み・合法手なしを判定します。同じ盤面・持ち駒・手番が4回出現すると通常の千日手は引き分けで終了し、連続王手の千日手では王手を続けた側を負けとします。

入玉宣言・持将棋の点数判定には未対応です。USIエンジンには現在の局面をSFENで渡すため、過去の手順を使った探索内の千日手判断は行いません。対局自体の千日手判定はアプリ側で行います。

## 主要なコンポーネント

コンポーネントは [app/components](app/components) にあります。

- `ShogiBoard`: 盤面描画とクリック処理。
- `HandsPanel`: 持ち駒表示・選択。
- `KifuPanel`: 日本語棋譜表示（同/成/不成/打）。
- `SettingsPanel`: 先手/後手・AI設定の入力。
- `StatusPanel`: 手番/勝敗/王手表示。
- `ControlsPanel`: リセット・設定戻り。
- `PromotionModal`: 成/不成の選択モーダル。

## 注意

- USIエンジンが利用不可の場合、ローカルAIに自動フォールバックします。
- エンジンの評価関数（nn.bin）は実行ファイルと対応するものを使用してください。
