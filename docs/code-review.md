# コードレビューと改善記録

2026年10月28日。対局画面、将棋ルール、探索、USI連携、設定・結果保存、テストを対象にレビューし、以下を修正しました。

## 修正した問題

| 項目             | 修正前                                                             | 修正後                                                                            |
| ---------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| 状態管理         | 対局画面内の多数のstate更新と非同期処理が混在                      | `game.ts`の純粋なReducer、`useGame.ts`の非同期処理、画面表示を分離                |
| 古い応答         | UI側の中止処理に依存                                               | 通信とWorkerの中止に加え、対局IDと手数で古い着手を拒否                            |
| 画面の応答性     | ローカル探索がメインスレッドを占有                                 | Web Workerで探索。利用不可・起動失敗時は探索予算100msの互換処理                           |
| 探索             | sort比較ごとに王手判定を繰り返す。未完了の深い探索で推奨手を上書き | 各手を一度だけ採点。探索が完了した深さの結果を保持。探索末端の詰みも検出          |
| 盤面コピー       | 毎回すべての駒オブジェクトをコピー                                 | 更新した行と持ち駒だけをコピー。変更のない駒は参照を共有                          |
| 描画             | 評価更新・駒の選択で盤面全体の描画処理を実行                       | 盤面・各マス・棋譜行をmemo化。グラフの座標・線・点も再利用                        |
| 合法手           | 打ち歩詰めを許す。外部の指し手を未検証で適用                       | 打ち歩詰めを除外し、エンジン応答も合法手と照合。玉を取る手を許可しない            |
| 終局             | 詰み以外の合法手なし・千日手に未対応                               | 合法手なし、通常の千日手、連続王手の千日手を判定                                  |
| 棋譜             | 「と成」などの二重の成り表記、不成の記録漏れ                       | 移動前の駒名と実際の成り選択を別に記録                                            |
| エンジン負荷     | リクエスト数に応じて無制限に子プロセスを起動                       | 同時2件・待機16件。中止時は終了を確認して枠を解放                                 |
| API入力          | 型アサーションだけで処理。壊れたJSONで例外                         | 64KiB制限、JSON・盤面・持ち駒・探索条件の検証。400/413で応答                      |
| USI応答          | 別候補や探索境界のスコアを採用する可能性                           | 主候補の確定スコアを採用し、指し手の座標と形式も検証                              |
| 設定・保存       | 保存不可で対局開始が中断。別タブで設定が変わる可能性               | 保存例外時はメモリへ退避。対局中の設定は固定。保存結果を検証                      |
| 重複コード       | 駒画像・棋譜表記・設定選択肢が重複                                 | 共通化し、未使用のAI設定パネルを削除                                              |
| アクセシビリティ | 成り選択でフォーカスが背後に移る                                   | ダイアログ名・フォーカス移動・Tab制御・Escape操作を追加。ページ言語を日本語に修正 |

## 探索処理の計測

Node.js v24.22.1、macOS arm64、開始局面で測定。ウォームアップ後に同じ処理を5回計測した中央値です。改善前のソースを別の一時ディレクトリに保存して比較しました。

| 処理            | 繰り返し回数 |  改善前 |  改善後 |
| --------------- | -----------: | ------: | ------: |
| 王手判定        |       10,000 |  9.87ms |  4.51ms |
| 合法手生成      |          500 | 21.80ms |  8.79ms |
| 手の並べ替え    |          500 | 39.17ms |  5.44ms |
| 深さ2の固定探索 |           10 | 56.34ms | 20.69ms |

これは開始局面での処理時間の比較であり、全局面で同じ高速化率や棋力向上を保証するものではありません。現在の実装は`npm run benchmark`で再計測できます。

## 検証

- `npm test`：30件。開始局面の合法手数30手/2手先900局面、直接の利き判定と従来方式の比較、打ち歩詰め、成り・不成、千日手、古い応答、API入力、子プロセス中止・異常終了・同時実行制限など。
- `npm run lint`、`npm run build`。
- Chromiumで、探索中の盤面操作とタイマー継続、Worker起動、先手/後手、ヒントからの着手、成り選択、AI応答、評価グラフ、リセット、別タブの設定変更、保存拒否時の対局開始を確認。
- 本番ビルドで実際のやねうら王を使い、指し手・ヒント・評価値と不正リクエストへの応答を確認。
- 1024×600〜1440×900のPC画面で全体のスクロールが発生せず、長い棋譜だけが内部スクロールすることを確認。スマートフォン幅では横スクロールが発生しないことを確認。

## 残る制約

- 入玉宣言・持将棋の点数判定には未対応です。通常の千日手はアプリ上では引き分けとして終了します。反則や千日手の条件は[日本将棋連盟の対局規則](https://www.shogi.or.jp/match/taikyoku_rules/)を参照しました。
- エンジンには現在のSFENを渡します。アプリは対局の千日手を判定しますが、エンジン探索に過去の対局手順は渡していません。
- エンジンの同時実行制限はサーバープロセス単位です。複数のインスタンス間では共有しません。
- 保存が拒否された場合のメモリ上の設定・結果は、ページを再読み込みすると失われます。
- 本レビューでは依存ライブラリのバージョン変更とデプロイは行っていません。
